# cryptopro-offline-crl

Списки отзыва (CRL) для КриптоПро CSP на серверах без выхода в интернет. Один хост скачивает списки и кладёт их в общую папку, остальные устанавливают их оттуда в локальное хранилище. Проверка отзыва при подписи находит свежий список на месте и не ждёт сетевого таймаута.

## Зачем

Если в хранилище нет действующего списка отзыва, КриптоПро при проверке сертификата идёт за ним по адресу из сертификата. На сервере с закрытым исходящим трафиком каждая такая попытка заканчивается таймаутом, и подпись в браузере или в программе ЭДО зависает на несколько секунд, а то и дольше.

Списка УЦ, выдавшего сертификат, для этого мало. Отзыв проверяется у каждого звена цепочки: у сертификата пользователя по списку УЦ, у сертификата УЦ по списку головного УЦ. Если второго списка нет, цепочка не строится с ошибкой `0x80092013` («сервер отзыва недоступен»), даже когда первый на месте. Поэтому точки распространения собираются по всей цепочке.

## Как устроено

```
интернет ──► Publish-Crl.ps1 ──► общая папка (CrlRoot)
             (хост с выходом               │
              в интернет)                  ▼
                                   Install-Crl.ps1 на каждом сервере
                                           │
                                           ▼
                           хранилище mCA (промежуточные ЦС компьютера)
```

**`Publish-Crl.ps1`**

1. Обходит подкаталоги `KeysRoot`, в которых лежат файловые контейнеры КриптоПро. Сертификат берётся из файла `.cer` в каталоге контейнера, а если его нет — из самого контейнера через `csptest -expcert` по дружественному имени из `name.key`.
2. Строит цепочку каждого сертификата и собирает http-адреса из расширения CRL Distribution Points всех звеньев.
3. Адреса с одинаковым именем файла считает зеркалами одного списка и перебирает до первого успешного скачивания.
4. Скачивает через BITS. Файл должен начинаться как DER (`0x30`), иначе он отбрасывается: это отсекает HTML-страницы ошибок.
5. Если содержимое изменилось, пишет файл под временным именем и ставит на место через `ReplaceFile`. Читающий видит либо прежний файл, либо новый. Пока файл открыт на чтение (соседний публикатор считает его хэш), замена повторяется до 30 секунд.
6. Если ни одно зеркало не ответило, оставляет прежнюю копию.
7. Список, который перестал встречаться в разборе два прогона подряд, переносит в `CrlRoot\_retired`.

Публикаторов может быть несколько: временные имена содержат хост и GUID, а одинаковое содержимое повторно не записывается.

Контейнер, в котором лежат одни ключи без сертификата, — обычное дело (на рабочем месте бухгалтерии таких оказалось 6 из 10). Разбирать в нём нечего, поэтому кодом возврата это не считается: `csptest` отвечает `SCARD_E_NO_SUCH_CERTIFICATE` по тому типу ключа, который в контейнере есть, и `NTE_KEYSET_NOT_DEF` по остальным. Любой другой код и таймаут остаются «прочитать не удалось» — заблокированный носитель пустым контейнером не выглядит.

**`Install-Crl.ps1`** копирует каждый `.crl` из `CrlRoot` во временный каталог и ставит командой `certmgr -inst -store mCA -crl`. Уже установленный файл пропускается: сначала по размеру и времени изменения, затем по SHA256. Состояние хранится в `StateRoot`.

## Требования

- Windows PowerShell 5.1.
- КриптоПро CSP на всех хостах: `certmgr.exe` для установки, `csptest.exe` и ГОСТ-провайдер для разбора цепочек на публикаторе.
- Публикатор: исходящий HTTP (TCP 80) для службы BITS, чтение каталога контейнеров, запись в `CrlRoot`. Контейнеры без файла `.cer` должны быть видны КриптоПро на этом хосте: сертификат из них извлекается через CSP.
- Остальные хосты: чтение `CrlRoot`, доступ в интернет не нужен.

Задачи работают от `SYSTEM`, поэтому в сети они выступают учётной записью компьютера (`ДОМЕН\ХОСТ$`). Права на общую папку выдаются компьютерам или их группе, а не пользователям.

## Установка

1. Положите скрипты в каталог, доступный хостам на чтение, например в общую папку со скриптами.
2. Рядом со скриптами создайте `CryptoCRL.local.psd1` (UTF-8 с BOM, если в путях есть кириллица):

   ```powershell
   @{
     KeysRoot = 'D:\Keys'                        # каталог с контейнерами, нужен Publish-Crl
     CrlRoot  = '\\example.local\share\CRL'      # каталог публикации, нужен обоим
   }
   ```

   Файл общий для обоих скриптов, каждый берёт из него свои параметры. Параметр командной строки важнее файла. В репозиторий файл не попадает: `.gitignore` пропускает только перечисленные в нём файлы.

3. На публикаторе разрешите исходящий трафик службе BITS, если он закрыт:

   ```powershell
   New-NetFirewallRule -DisplayName 'Загрузка списков отзыва (BITS)' -Direction Outbound `
     -Service BITS -Protocol TCP -RemotePort 80 -Action Allow
   ```

4. Создайте задачи планировщика от `SYSTEM`. Публикация раз в 4 часа, установка на 30 минут позже:

   ```powershell
   $dir = '\\example.local\Scripts\cryptopro-offline-crl'
   $p = New-ScheduledTaskPrincipal -UserId 'SYSTEM' -LogonType ServiceAccount -RunLevel Highest
   $s = New-ScheduledTaskSettingsSet -ExecutionTimeLimit (New-TimeSpan -Minutes 30) -StartWhenAvailable

   foreach ($t in @(@{ Name = 'Publish-Crl'; At = '00:00' }, @{ Name = 'Install-Crl'; At = '00:30' })) {
     $a = New-ScheduledTaskAction -Execute 'powershell.exe' `
            -Argument ('-NoProfile -NonInteractive -ExecutionPolicy Bypass -File "{0}\{1}.ps1"' -f $dir, $t.Name)
     $tr = New-ScheduledTaskTrigger -Once -At $t.At -RepetitionInterval (New-TimeSpan -Hours 4)
     Register-ScheduledTask -TaskName $t.Name -Action $a -Trigger $tr -Principal $p -Settings $s
   }
   ```

   **Хост с интернетом публикует сам себе.** Если общей папки нет, а выход в интернет есть у каждого сервера (рабочая группа, малая площадка), `CrlRoot` задаётся локальным каталогом и обе задачи сводятся в одну — с двумя вызовами подряд:

   ```powershell
   $a = New-ScheduledTaskAction -Execute 'powershell.exe' -Argument (
     '-NoProfile -NonInteractive -ExecutionPolicy Bypass -Command "& ''{0}\Publish-Crl.ps1''; $p = $LASTEXITCODE; & ''{0}\Install-Crl.ps1''; $i = $LASTEXITCODE; if ($i) {{ exit $i }}; exit $p"' -f $dir)
   ```

   `-Command` сам по себе возвращает не код скрипта, а только признак успеха последней команды, поэтому коды обоих вызовов передаются явно: код установки, если она не удалась, иначе код публикации. В строке старта журналов (`publish-ddMMyyyy.log`, `install-ddMMyyyy.log`) стоит версия скрипта.

   `Publish-Crl` нужен только на публикаторах. В домене задачи удобно раздавать элементом «Назначенные задания» групповой политики с нацеливанием на группу компьютеров.

5. Запустите задачи вручную и проверьте код возврата и логи. Ручной запуск скрипта из своей сессии права учётной записи компьютера не проверяет.

## Параметры

| Параметр | Скрипт | По умолчанию | Назначение |
|---|---|---|---|
| `KeysRoot` | Publish | — | каталог с контейнерами КриптоПро |
| `CrlRoot` | оба | — | каталог публикации |
| `StateRoot` | Install | `C:\ProgramData\Scripts\CryptoCRL\state` | отметки установленных списков |
| `LogRoot` | оба | `C:\ProgramData\Scripts\Logs\CryptoCRL` | логи `publish-ddMMyyyy.log`, `install-ddMMyyyy.log` |
| `LogRetentionDays` | оба | `14` | срок хранения логов |
| `TimeoutSec` | Publish | `60` | ожидание одного зеркала |
| `Force` | Install | — | переустановить все списки |

Подкаталоги `BACKUP` и `KEYS-ARCHIVE` в корне `KeysRoot` в разбор не входят: туда кладут копии и выведенные из работы контейнеры.

## Коды возврата

`Publish-Crl.ps1`:

| Код | Значение |
|---|---|
| 0 | все списки подтверждены, и каждый читаемый контейнер разобран |
| 1 | часть списков не скачалась или часть контейнеров не прочитана; прежние копии на месте |
| 2 | не задан `KeysRoot` или `CrlRoot`, либо не читается `CryptoCRL.local.psd1` |
| 8 | каталог контейнеров недоступен |
| 9 | каталог публикации пуст или не подтверждён ни один список |
| 10 | необработанная ошибка |
| 11 | в сертификатах нет ни одной точки распространения |

`Install-Crl.ps1`:

| Код | Значение |
|---|---|
| 0 | все списки установлены или уже были установлены |
| 1 | часть списков не установилась |
| 2 | не задан `CrlRoot` или не читается `CryptoCRL.local.psd1` |
| 8 | каталог публикации недоступен |
| 10 | необработанная ошибка |
| 11 | в каталоге публикации нет ни одного `.crl` |
| 13 | не найден `certmgr.exe` |

## Проверка

Тесты не требуют КриптоПро и ничего не меняют в системе:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Tests\CryptoCRL.Tests.ps1
```

Проверка на сервере — построение цепочки с обязательной проверкой отзыва всех звеньев при очищенном кэше:

```powershell
$cert = New-Object System.Security.Cryptography.X509Certificates.X509Certificate2 'C:\temp\user.cer'
certutil -urlcache crl delete | Out-Null
$ch = New-Object System.Security.Cryptography.X509Certificates.X509Chain
$ch.ChainPolicy.RevocationMode = 'Online'
$ch.ChainPolicy.RevocationFlag = 'EntireChain'
[void]$ch.Build($cert)
$i = 0
foreach ($e in $ch.ChainElements) {
  '[{0}] {1} -> {2}' -f $i++, ($e.Certificate.Subject -split ',')[0],
    $(if ($e.ChainElementStatus.Count) { ($e.ChainElementStatus.Status) -join '+' } else { 'ok' })
}
```

Каждое звено должно быть `ok`. `VerificationFlags` здесь не задавайте: `IgnoreCertificateAuthorityRevocationUnknown` скрывает как раз отсутствующий список головного УЦ.

## Ограничения

- Загружаются только http-адреса. Адреса ldap пропускаются.
- Зеркала сводятся по имени файла. Если два разных УЦ опубликуют разные списки под одним именем, они будут перезаписывать друг друга; признак — список, который обновляется на каждом прогоне.
- Сертификаты из пользовательских хранилищ не разбираются: задача работает от `SYSTEM` и видит только каталог контейнеров.
- Снятый с публикации список из хранилищ на хостах не удаляется.
- Снятие с публикации переносит в `_retired` любой `.crl` в `CrlRoot`, которого нет в разборе этого публикатора. Несколько публикаторов над одним `CrlRoot` должны разбирать один и тот же набор контейнеров, иначе они снимут списки друг друга. С версии 1.1.0 снятие работает и на площадках с контейнерами без сертификата, где раньше не запускалось.
- Имя контейнера с обратным слэшем или управляющим символом отвергается: оно передаётся в командную строку `csptest`, запущенного от `SYSTEM`.
- Проверка первого байта отсеивает страницы ошибок, но не проверяет подлинность списка. Подлинность проверяет КриптоПро по подписи УЦ.
